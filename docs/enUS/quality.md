## Test matrix

The suite exercises the following areas. (Specific test names and any newly
added cases are filled in during backfill.)

- **Canonicalization** — golden vectors for Unicode, HTML characters, empty
  values, nested objects, and numeric boundaries; byte-for-byte stability.
- **Envelope parsing** — duplicate keys, trailing data, unknown fields, mixed
  Base64 alphabets, size cap.
- **KeyRing** — concurrency, validity-window boundaries, revoke/disable,
  nil/wrong-length keys.
- **Rollback state** — missing/corrupt/truncated/oversized state, atomic-write
  and permission failures, `lifetime` vs `trial`/`subscription` policy.
- **Revocation** — expired/future `issued_at`, duplicate IDs, over-cap lists,
  bad signature, unknown key.
- **Fingerprint** — order-independence, empty components, namespace/HMAC
  isolation, request-code stability.
- **Version** — pre-release/invalid strings, fail-closed on missing
  `ProductVersion`.
- **Result facade** — defensive copies of slices/maps.
- **CLI (`cmd/license-tool`)** — per-subcommand argument errors, exit codes,
  stdout/stderr separation, `-force` overwrite refusal, no sensitive output.

## Fuzz strategy

- Fuzz targets (`pkg/license`): `FuzzParseEnvelope`, `FuzzCanonicalBytes`,
  `FuzzLoadRevocationList`, `FuzzRollbackStateLoad`.
- Corpus and temporary fuzz files are **not** committed to the repository.

Every push/PR smoke-runs all four targets for a short time (a matrix job in
`.github/workflows/ci.yml`, `-fuzztime=30s` each) to ensure they build and
execute. A nightly workflow (`.github/workflows/fuzz-nightly.yml`) runs a longer
campaign (`-fuzztime=10m` per target) and archives any crash corpus as a
build artifact so a discovered failure is reproducible.
